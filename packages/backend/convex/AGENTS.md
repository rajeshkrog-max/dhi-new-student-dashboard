# Convex backend

## Overview

The whole backend: sign in (Better Auth, Google only), the student, their one check and its 18 answers, the saved result, the phone step (leads), report feedback, and the queue that copies leads and feedback to the team's Google Sheet. Every function acts only on the signed in student's own rows; the browser is untrusted. **Read `convex/_generated/ai/guidelines.md` before writing any Convex code** (it overrides what you may remember about Convex).

## Conventions

- Errors a page can read are `ConvexError({ code })` through `fail("code")`. Never put personal data in a message or a log line (log counts and ids only).
- No function takes a student id, email or auth user id as input. Find the student with `requireStudent`.
- Expected refusals in `leads.submit` and `feedback.submit` return `{ ok: false, code }` instead of throwing, so the rate limit count stays.
- Every function has `args` and `returns` validators. New tables and fields are additive: never rename or remove one in the same release as the code that stops using it.
- Saved rows that are meant to be final (`results`, `resultFlags`, `consents`, `consentTexts`) are never patched or deleted by app code. `convex/results.test.ts` scans the sources to enforce this for results. A consent text changes only as a new version.
- Flags (`selfDoubt`, `lowMood`, and the rest) live only in `resultFlags` and are returned only to the owner. Nothing about a result goes into the Sheet copy, analytics or the leaderboard.
- `ENGINE_VERSION` in `packages/engine/score.js` is bumped by hand when scoring output changes; `convex/score.lock.test.ts` and `tests/fixtures/score-lock.json` (in this package) enforce it (see `apps/joining/public/dhiinterviews/js/engine/AGENTS.md`).
- The report copy never carries flags: the render payload is built with `NO_FLAGS` (in `resultsCore.ts`, the only place flag names may appear), and a copy is drawn only from a signed, short lived render token, never from anything a browser sends. `REPORT_VERSION` must equal `VERSION` in `reportText.js` (the funnel's `tests/report-text.test.js` fails if not, because this package must not read an app file); bump both together when the report's words or layout change.
- Secrets live only in Convex environment variables, per deployment (declared in `convex.config.ts`). `TEST_SIGNIN_ENABLED` is for dev and preview only, never production.
- A picture path for any place other than the student's own `students.me` (the report copy payload, the team list, a leaderboard row, later the shared report) comes only from `pictureFor` in `avatarState.ts`; leaderboard rows use `leaderboardPictureFor`. The Google address, the storage id and the ETag never leave the server, and the only request to Google is `fetchPicture`, called from `avatars.sync`. Removing a picture deletes its file in the same step.
- The picture switches are read trimmed and ignoring case: `PROFILE_PICTURE_ENABLED` is on unless it is `false`, `0`, `no` or `off`; `PICTURE_CONSENT_REQUIRED` unset means nobody is asked and any other value brings the asked flow back; `LEADERBOARD_PICTURES_ENABLED` is off unless an explicit yes.
- The private report link works only when both `SHARE_LINK_SECRET` and `PUBLIC_SHARE_ENABLED` (`true`, `1`, `yes` or `on`; unset means off) are set, and the secret is read only through `shareSecret(env)`. Dev and production both have both (the same secret value, by the owner's choice; production was switched on 2026-10-11). Unsetting `PUBLIC_SHARE_ENABLED` stops every link at once. Anything a stranger sees comes only from `sharePayload.ts`: flags are `NO_FLAGS`, `state` is sent empty and each area's `said` is null, because the mood split and the quoted answers give `lowMood` and `selfDoubt` away (the saved PDF copy keeps them, only the student and the team open it). `shares.disable` and `shares.adminOff` call `rotatePictureKey`, so the picture address in an old payload stops working. No code is ever logged; the one allowed log line is the fixed words for a lost race in `shareHttp.ts`.
- Challenge counts and ranks have one writer each. `validCount` and `lastValidAt` are written only through `recount` (the job and the review commands). `rank`, `toNext` and `nextRank` are written only by `challengeBoard.run`, and after the deadline by `dropEntry` when a student leaves or erases. The public leaderboard row is built only by `rowFor` (rank, displayName, cls, style, valid, avatar; a test scans the keys), and it never holds an id, email, phone, age, flag or last name.
- The end date is optional (spec 0008): `CHALLENGE_ENDS_AT` is an ISO date with an offset, read on every call through `endsAtOf(env)`. Unset, empty or malformed means the challenge never ends (nobody refused, nothing rejected for time, no freeze, `endsAt: null` in `me` and `leaderboard`), and a malformed value is logged. Tests that exercise the deadline set it from `TEST_ENDS_AT_ISO` in `tests/convexTestUtils.ts`. Production has never had it, so the first production deploy from this branch removes the 30 October deadline.
- With an end date set, the board freezes: the first `challengeBoard.run` that began after it settles every referral from its stored step times and writes the final snapshot with `frozen: true`; later runs return at once. A later `reject` or `restore` (spec 0019) changes live counts and `challengeAdmin:ranking`, never the public board, so `restore` settles the referral itself instead of waiting for a job that no longer runs. Everything in `challengeAdmin.ts` is internal and must stay out of `http.ts` and the bridge; it prints personal data, so it is never run in an AI session and never logs.

- House functions start with `requireMember`, which also refuses a student who has not agreed, has no parent record (under 18, or the flag is missing), or has withdrawn. Only the functions in `consent.ts`, `sharing.ts`, `access.ts` and `dataRights.ts` use `requireMemberAllowLocked`, and `houseConsent.test.ts` scans for that.
- Events are append only. Only `eventLog.ts` inserts one, only `eventData.ts` reads or deletes one outside it, and no public function takes or returns one. A refusal from `recordEvent` rolls back the room's own write. A payload holds ids, numbers, booleans and fixed codes, never free text.
- Every house table needs an entry in `dataMap.ts` (a test fails if it is missing). A room that stores student data also adds its `roomRegistry.ts` entry (exporter and eraser) and its kind codes in `accessRules.ts`. Staff see a student's named data only through `staffRead`, and class totals only through `classTotal`. The one other writer of the view record in `staffRead.ts` is `recordGroupLook`, for a look at a study hour recording.
- The consent notice and the parent wording are drafts (`HOUSE_WORDS_APPROVED` is false in `consentText.ts`). Use only made up people until the owner approves the words and the legal check is done (house spec 0005).
- Erase needs `ERASURE_HASH_SECRET` on the deployment, or it answers `erase_not_configured`. It is set on development, not on production.
- The free plan counts every scheduled run as a call and every row read (house spec 0029). A job that runs on a timer must stop after one indexed read when it has nothing to do, and must not read the same rows again each time: a cursor moves past what it read, and rows it cannot handle are retried rarely.
- Many writes for one student and one day at once conflict and are retried; about 10 at once is the limit seen live (`eventProof:race`). Rooms should not write more than a few events for one student at the same moment.
- A room follows the pattern of `moods.ts` and `habits.ts`: the function starts with `requireMember` and a student role check, then the rate limit (every attempt counts), then validation, then a write that is today only and reads the clock once, and the event holds a code only. Free text lives in the room's own table. Add the room's exporter and eraser to `roomRegistry.ts`, its tables to `dataMap.ts`, and a dev only `*Proof.ts` race check (it refuses to run where the test sign in is off). A room's screen words are drafts until its switch is true: `HOUSE_WORDS_APPROVED`, `MOOD_WORDS_APPROVED`, `HABIT_WORDS_APPROVED`, `SLEEP_WORDS_APPROVED`, `BRAIN_WORDS_APPROVED` and `DESK_WORDS_APPROVED` (in `deskRules.ts`, with a twin in the screen's `desk-words.ts`) are all false now.
- The Brain: `brainDays` is written only by `brainRollup.ts` and read only by `brainDay.ts`, `brainRoom.ts`, `brain.ts` and the dev helper (`brainRollup.test.ts` scans for both). A day with nothing logged has no value; a zero exists only for a thing that was expected and did not happen, once the day is over. A pattern, a lamp, the expression note and the support offer are worked out when the student looks and stored nowhere (only which pattern a student hid, in `brainHides`). The data kind `brain` is private to the student: no `staffRead`, `classTotal`, access log or view log in the Brain's files. A change of formula bumps `METRIC_VERSION` and the stored days are rebuilt from the events. `PATTERN_SOURCES_CONFIRMED` and `FOOD_PATTERN_ON` in `brainRules.ts` are owner gates and stay false. The one opening for anyone but the student is the weekly parent page (house spec 0022), kept in `parent*.ts` and never in the Brain's files: it reads the days through `windowRows` and the pure rules, and a parent look is written by `parentReport.ts`. `parentRules.weekOf` is the only place the page is built, from a short list of allowed fields (a test scans for pattern, support, movement and input code).

## Gotchas

- A sharded rate limit in the limiter component gives every shard its own random window start unless the config has `start`, so a burst gets extra tokens as shards reset one by one. Set `start: 0` on a sharded fixed window you want to behave like "N a minute" (`shareRead`, `shareBad`). With 16 shards each holds a sixteenth, so the cap is a little under N, never above. `convex-test` runs one mutation at a time, so it cannot show a write race; check that live (40 readers at once), and expect 429, never 500, on a lost race.
- `convex/_generated/` is committed. `convex dev` regenerates it; if you add a file without running it, add the module to `_generated/api.d.ts` by hand (the same lines codegen writes).
- Test files (`*.test.ts`) sit beside the code but are not bundled. `import.meta` is allowed only in them (and in `tests/convexTestUtils.ts`, which is deliberately outside `convex/`).
- `scoring.ts` imports `@dhi/engine/questions` and `@dhi/engine/score` (`packages/engine/`) for their side effect. They must stay plain ES5 scripts that fall back to `globalThis`.
- This package must not import or read anything from an app (`apps/*`): the dependency runs app to package. Checks that need an app file live in that app's tests. Apps import only the named exports in `package.json` (`@dhi/backend/api`, `consentText`, `dayRules`, `moodRules`, `habitCodes`, `sleepRules`, `blogRules`, `foodRules`, `hourRules`, `deskRules`, `sessionRules`, `counselRules`, `hourCallRules`, `brainCodes`, `feedbackRules`, `challengeRules`, `reportVersion`).
- The report copy runs on Cloudflare Browser Run and needs `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_API_TOKEN`, `REPORT_RENDER_SECRET` (a different value per deployment) and `REPORT_RENDER_BASE_URL` (a public address; dev needs a deployed Pages preview, Browser Run cannot reach localhost). The Workers Free plan allows one request every 10 seconds and 10 minutes of browser time a day, so jobs run one at a time about 11 seconds apart and a "time limit exceeded" 429 waits for the next UTC day.
- Production is `abundant-caiman-975`, dev is `proper-camel-616` (`.env.local`). The browser tests refuse to run against production.
- A picture check is limited to one every 10 minutes for each student, so a fetch right after a team unblock or a sign in can wait up to 10 minutes (Restore has its own limit of 3 an hour). Nothing needs doing by hand: the next page load asks again. The Pages forwarder keeps an image at the edge for 50 minutes and tells a browser to keep it for 10 (Pages Functions ignore `_headers`, so its headers are set in code), so a removed picture can stay visible for at most an hour.
- Block or unblock a picture from a terminal: `npx convex run avatars:adminBlock '{"email":"student@example.com"}'` (and `adminUnblock`). Add `--prod` only on purpose.
- After switching to the asked mode (`PICTURE_CONSENT_REQUIRED` set), run `npx convex run avatars:dropUnagreed` once (add `--prod` on purpose). It deletes the copied pictures of students who have not agreed, including those who never come back; `ensure` does the same for each student who does.
